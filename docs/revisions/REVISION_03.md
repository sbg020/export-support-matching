> **사용 방법**
> 이 파일을 프로젝트 루트(`CLAUDE.md`와 같은 위치)에 두고 Claude Code에 다음과 같이 요청한다.
> `CLAUDE.md, docs/revisions/revision_01.md, docs/revisions/REVISION_02.md, REVISION_03.md를 모두 읽고 REVISION_03을 로컬과 배포 사이트에 반영해줘.`
>
> **우선순위**
> `CLAUDE.md`, revision_01, REVISION_02의 서비스 원칙(가상 데이터 금지, 결측값 `-`, 자격·적합도 분리, 근거 없는 점수 금지, 기존 저장 키 보존, 접근성)은 그대로 유지한다. 이 문서와 충돌하는 부분은 이 문서를 따른다. 이 문서에는 비밀값이 없다.

> 로컬 개발 환경과 기존 배포 사이트 `https://exportsupportmatching.vercel.app/`를 모두 갱신한다. 이번 요청은 커밋·푸시·배포까지 포함한다. `main` 병합은 하지 않는다.

## 1. 목표와 반드시 지킬 제약

**목표**

1. 왼쪽 사이드바를 상단 메뉴로 옮기고, 주 메뉴에 마우스를 올리면 하위 메뉴가 아래로 펼쳐지게 한다.
2. 로그인하면 수출 로드맵에서 시작하고, 로그아웃하면 홈으로 돌아간다.
3. 로그인 상태에서 프로필을 누르면 `기업 프로필`·`로그아웃` 팝업이 뜬다.
4. 기업정보 입력 화면을 `기업 프로필` 하나로 합치고, 중복되는 기존 기업 프로필 화면을 지운다.
5. 관심·준비 중·신청완료 사업과 서류함을 새 주 메뉴 `지원사업 관리`로 모은다.

**반드시 지킬 제약**

1. **데이터를 지우거나 바꾸지 않는다.** (사용자 지시)
   - 브라우저 저장 키 `export-support-matching:profile:v1`(기업정보), `esm.applicationRecords.v1`(관리 기록), `esm.selfChecks.v1`(직접 확인 답), `esm.compareSelection.v1`(비교 선택, sessionStorage)의 이름·형식·값을 바꾸거나 지우지 않는다. 키를 옮기는 마이그레이션이나 초기화 코드도 넣지 않는다.
   - 로그아웃은 지금처럼 서버 세션만 끝낸다. 이 기기에 저장된 기업정보·관리 기록·직접 확인 답·비교 선택은 그대로 남긴다.
   - 화면을 지울 때 그 화면의 데이터를 지우는 코드를 실행하거나 추가하지 않는다. 지워도 되는 파일은 §9.1의 2개뿐이다.
   - `frontend/src/data/`(테스트 데이터 JSON), 정답 세트 xlsx, `docs/contracts/engine-cases.json`, `docs/data/`, `backend/`(모델·마이그레이션), 기존 문서는 지우거나 다시 만들지 않는다. 이번 개정에서는 테스트 데이터를 다시 변환하지 않는다.
   - Git 이력을 고치지 않는다. 강제 푸시, 기존 커밋 삭제, 브랜치 삭제, `git rm --cached`로 추적 해제를 하지 않는다.
   - 바뀌는 주소는 모두 리다이렉트로 남겨 북마크·공유 링크가 계속 열리게 한다 (§6.1, §7).
2. **이름만 바꾸는 메뉴는 이름만 바꾼다.** `나의 로드맵` → `수출 로드맵`, `지원사업 찾기` → `기업 맞춤 지원사업`. 이 두 섹션의 화면 내용과 주소(`/roadmap`, `/diagnose/result`, `/programs/recommended`)는 그대로다.
3. **그 밖의 화면 내용은 바꾸지 않는다.** 이 문서가 지정한 문구(§8)와 연결 대상만 고친다. 공고·판정·적합도·비교·커뮤니티·달력의 동작과 문구는 그대로다.
4. **접근성을 유지한다.** 키보드로 모든 메뉴와 팝업을 쓸 수 있고, 현재 위치는 `aria-current`와 글자 굵기·밑줄로도 구분하며, `Esc`로 닫히고, 포커스 표시가 보인다.

## 3. 상단 주 메뉴

### 3.1 구성과 순서

| 순서 | 주 메뉴 | 하위 메뉴 | 주 메뉴를 누르면 | 로그인 |
|---|---|---|---|---|
| 1 | **수출 로드맵** (기존 `나의 로드맵`, 이름만 변경) | 수출 로드맵 | `/roadmap` | 불필요 |
| 2 | **기업 맞춤 지원사업** (기존 `지원사업 찾기`, 이름만 변경) | 기업 진단 · 맞춤 추천 | `/diagnose/result` | 불필요 |
| 3 | **전체 지원사업** | 전체 공고 · 공고 달력 | `/programs` | 불필요 |
| 4 | **지원사업 관리** (신규, §7) | 관심·준비 중·신청완료 사업 · 서류함 | `/manage/programs` | 필요 |
| 5 | **커뮤니티** | 지원사업 후기 · 지원사업 정보방 | `/community/reviews` | 읽기는 불필요 |

- `constants/navigation.ts`의 `NAV_SECTIONS`를 위 순서·이름으로 바꾼다. `mypage` 섹션을 지우고 `manage` 섹션을 넣는다. 내부 섹션 키 `find`·`roadmap`은 그대로 둔다(이름만 변경). 마이페이지를 빼던 `SIDEBAR_SECTIONS`는 없애고 `NAV_SECTIONS` 5개를 그대로 쓴다.
- **메뉴 아이콘을 없앤다.** 지금 주 메뉴 왼쪽에 있는 돋보기(`IconSearch`)·목록(`IconListDetails`)·길(`IconRoute`)·말풍선(`IconMessages`) 아이콘을 상단 메뉴와 모바일 서랍 메뉴 모두에서 빼고 글자만 둔다. 쓰지 않게 된 `NavSection.icon`과 아이콘 import는 지운다. 화면 본문 안의 아이콘은 그대로다.
- **로고는 그대로 둔다.** `BrandLink`(아이콘 + `수출지원사업 매칭`, 누르면 `/`)를 헤더 왼쪽 끝에 둔다. 로그인 상태에서 누르면 §4 규칙에 따라 수출 로드맵이 열린다.
- **헤더 한 줄 배치:** `[로고] [주 메뉴 5개] ………… [로그인 버튼 또는 프로필]`. 주 메뉴는 한 줄에 들어가야 하고 줄바꿈하지 않는다(`white-space: nowrap`). 992px에서 넘치면 메뉴 사이 간격을 줄이고, 그래도 넘치면 상단 메뉴가 나오는 최소 폭을 1200px로 올린 뒤(그 아래는 서랍 메뉴) 보고서에 적는다.
- **현재 섹션 표시:** `aria-current="page"`, 굵은 글씨, 강조 글자색, 글자 아래 3px 강조선. 색만으로 구분하지 않는다. 홈·로그인·기업 프로필 화면에서는 어떤 주 메뉴도 선택 상태로 두지 않는다.
- **마우스를 올렸을 때의 반응은 그대로 둔다.** 지금 사이드바처럼 배경색(`--color-surface-sunken`)과 글자색이 바뀐다.

### 3.2 하위 메뉴 패널 (마우스를 올리면 아래로 펼침)

참고 이미지(위시켓 상단 메뉴)처럼, 주 메뉴에 마우스를 올리면 헤더 바로 아래에 전체 폭 패널이 펼쳐지고, 각 주 메뉴의 하위 메뉴가 그 주 메뉴 아래에 세로로 보인다. 배치 방식만 참고하고, 디자인은 복제하지 않고 기존 디자인 토큰과 컴포넌트로 만든다.

| 열 (주 메뉴 바로 아래) | 항목 |
|---|---|
| 수출 로드맵 | 수출 로드맵 |
| 기업 맞춤 지원사업 | 기업 진단, 맞춤 추천 |
| 전체 지원사업 | 전체 공고, 공고 달력 |
| 지원사업 관리 | 관심·준비 중·신청완료 사업, 서류함 |
| 커뮤니티 | 지원사업 후기, 지원사업 정보방 |

- **열기:** 데스크톱(992px 이상, 마우스처럼 hover가 되는 기기)에서 주 메뉴 영역에 마우스를 올리거나 키보드 포커스가 주 메뉴에 들어오면 연다. 다섯 열(하위 항목 9개)을 한꺼번에 보여 준다.
- **위치와 모양:** 각 열의 왼쪽 끝을 자기 주 메뉴의 왼쪽 끝에 맞춘다. 패널은 본문을 밀어내지 않고 본문 위에 겹치며(헤더 높이 `--header-height`는 그대로), 흰 배경·아래 경계선·옅은 그림자를 쓴다. 패널 안쪽 너비는 헤더와 같다(§3.5).
- **넣지 않는 것:** 참고 이미지 오른쪽의 홍보 카드, 패널 안에서 주 메뉴 이름을 다시 쓰는 열 제목, 근거 없는 설명·배지.
- **닫기:** 마우스가 헤더와 패널을 모두 벗어나고 150ms가 지나면 닫는다. `Esc`(포커스는 그 주 메뉴 링크로), 포커스가 헤더 밖으로 나갈 때, 항목을 누르거나 화면이 바뀔 때, 프로필 팝업을 열 때도 닫는다.
- **하위 항목 표시:** 현재 화면이면 `aria-current="page"`와 굵은 글씨·강조 글자색. 마우스를 올리면 글자색이 바뀐다. 각 항목은 그 화면으로 가는 링크다. 지원사업 관리 항목은 비로그인이면 로그인 화면으로 갔다가 로그인 후 돌아온다(§4).
- **접근성:** `<nav aria-label="주 메뉴">` 안에서 주 메뉴 `li`마다 하위 목록을 둔다. Tab 순서는 주 메뉴 → 그 하위 항목 → 다음 주 메뉴다. 패널이 닫혀 있으면 하위 목록은 `hidden`이라 Tab 순서와 화면낭독기에서 빠진다. 링크 목록이므로 `role="menu"`는 쓰지 않는다.
- **터치 기기:** hover가 없는 기기(`@media (hover: none)`)에서는 패널을 열지 않고, 주 메뉴를 누르면 지금처럼 그 섹션의 첫 화면으로 간다.
- `prefers-reduced-motion: reduce`이면 펼침 애니메이션 없이 바로 보인다.

### 3.3 모바일 (991px 이하)

- **지금 방식을 그대로 쓴다.** 헤더 왼쪽 메뉴 버튼(햄버거)을 누르면 왼쪽 서랍 메뉴가 열리고, 포커스 가두기와 `Esc`·바깥 누르기·화면 이동 시 닫힘도 그대로다.
- 헤더: `[메뉴 버튼] [로고] ……… [로그인 버튼 또는 프로필]` 그대로.
- 서랍: 로고와 주 메뉴 5개(새 순서·이름, 아이콘 없음). 하위 메뉴 패널은 모바일에 넣지 않는다. 하위 화면은 각 화면 제목 아래의 하위 메뉴 탭으로 이동한다.

### 3.4 화면 안의 하위 메뉴 (`SectionNav`)

- 각 화면 제목 아래의 하위 메뉴 탭은 그대로 둔다. 섹션별 항목은 §3.1 표를 따른다.
- 마이페이지에서만 보이던 오른쪽 끝 `로그아웃` 버튼은 지운다. 로그아웃은 프로필 팝업에서 한다(§5).

### 3.5 레이아웃과 좌우 여백

- `App.vue`에서 `AppSidebar`를 빼고, 헤더 · 본문 · 바닥글을 위에서 아래로 쌓는다. 헤더는 지금처럼 화면 위에 고정(sticky)한다.
- 헤더 안쪽은 본문(`.page`)과 같은 최대 너비(`--content-max`, 1280px)와 좌우 여백(`--page-gutter`)으로 가운데 정렬한다. 로고의 왼쪽 끝과 프로필의 오른쪽 끝이 본문 좌우 끝에 맞는다. 하위 메뉴 패널 안쪽도 같다.
- 사이드바 자리(256px)가 없어지므로 본문은 화면 가운데에 오고 좌우 여백이 같아진다 (예: 1920px 화면에서 좌우 각 320px). `--sidebar-width`를 쓰는 곳을 없애고, 쓰는 곳이 없으면 토큰 정의도 지운다.
- 홈 첫 영역처럼 화면 전체 폭을 쓰는 배경은 그대로다. 하단 비교 바(`CompareDock`)와 토스트는 화면 기준으로 놓여 있으므로 위치를 바꾸지 않는다.

## 4. 로그인 후 첫 화면과 로그아웃

| 상황 | 이동 |
|---|---|
| 로그인 성공, 안전한 `redirect`가 있음 | `redirect` (로그인이 필요한 화면이나 동작에서 넘어온 경우) |
| 로그인 성공, `redirect`가 없거나 허용되지 않음 | **수출 로드맵** (`/roadmap`) |
| 로그인 상태에서 홈(`/`)에 접근 | 수출 로드맵으로 보낸다. 로그인 전 첫 화면(홈)은 보이지 않는다 |
| 로그인 상태에서 `/login`에 접근 | 안전한 `redirect` 또는 수출 로드맵 |
| 로그아웃 | 홈(`/`, 로그인 전 첫 화면) |

- **`redirect`를 붙이는 곳은 지금 그대로 둔다:** 로그인이 필요한 화면 접근(라우터 가드, 예: 지원사업 관리), 로그인이 필요한 동작(맞춤 추천 카드·공고 상세의 `관심사업 저장`, 커뮤니티 `글쓰기`와 글 보기의 로그인 필요 동작). 로그인 후 그 화면으로 돌아간다.
- **`redirect`를 빼는 곳:** 헤더의 `로그인` 버튼, 홈의 `추천받기`(비로그인). 로그인 후 수출 로드맵으로 간다.
- `redirect` 검사(`safeRedirect`)는 그대로 쓴다. 거부되면 `/` 대신 수출 로드맵으로 보낸다.
- 홈의 `추천받기`: 비로그인이면 `/login`(redirect 없음)으로 간다. 로그인 상태 분기는 로그인 상태에서 홈이 보이지 않으므로 실제로 쓰이지 않지만, 남겨 두면 수출 로드맵으로 보낸다. 홈 화면의 내용은 바꾸지 않는다.
- **로그아웃:** `auth.logout()` → 토스트 `로그아웃했습니다. 이 기기에 저장한 기업정보는 그대로 남아 있습니다.`(기존 문구) → 홈(`/`). 이 기기에 저장된 데이터는 지우지 않는다(§1).
- 위 규칙은 `router/index.ts`의 `beforeEach`와 `LoginView.vue`의 이동 대상에 넣는다. 로그인 상태 확인 중(`unknown`)에는 지금처럼 확인이 끝난 뒤 판단한다.

## 5. 프로필 팝업 (로그인 상태)

- **버튼:** 헤더 오른쪽의 원형 프로필(계정 아이디 첫 글자, 지름 40px)은 이제 링크가 아니라 버튼이다. `aria-expanded`와 `aria-controls`를 달고, `aria-label`은 `계정 메뉴 (ADMIN 계정)`처럼 실제 아이디를 넣는다.
- **팝업 항목 (이 2개만):**

  | 항목 | 동작 |
  |---|---|
  | 기업 프로필 | `/profile`로 이동 (§6) |
  | 로그아웃 | §4의 로그아웃 |

- **모양:** 프로필 버튼 아래, 오른쪽 끝에 맞춘 작은 카드(흰 배경, 테두리, `--shadow-md`, 반경 12px, 최소 폭 160px, 항목 높이 44px). 항목은 링크 1개와 버튼 1개다.
- **열고 닫기:** 누르면 열고 다시 누르면 닫는다. `Esc`(포커스는 프로필 버튼으로), 바깥 누르기, 항목 선택, 화면 이동, Tab으로 팝업 밖으로 나갈 때, 하위 메뉴 패널이 열릴 때 닫는다. 키보드로 열면 첫 항목에 포커스를 둔다.
- 기업 프로필 화면에 있으면 프로필 버튼에 지금의 선택 고리(테두리)를 표시한다.
- **비로그인:** `로그인` 버튼(→ `/login`, redirect 없음). 로그인 화면에서는 지금처럼 숨긴다. **확인 중:** 자리만 비워 둔다(가짜 아바타·스켈레톤 없음).
- 모바일에서도 같은 팝업을 쓴다.

## 6. 기업 프로필 (기존 `기업정보 입력·저장` 화면)

### 6.1 이름과 주소

- 지금 `지원사업 찾기`에 있는 기업정보 입력 화면(`views/diagnose/DiagnoseInputView.vue`)을 **`기업 프로필`**이라고 부른다.
  - 화면 제목: `기업정보 입력` → `기업 프로필`
  - 브라우저 탭 제목: `기업정보 입력·저장` → `기업 프로필`
- 주소는 `/profile`, 경로 이름은 `company-profile`이다. 어느 섹션에도 속하지 않으므로(`meta.section` 없음) 상단 주 메뉴와 하위 메뉴 탭에 표시하지 않는다.
- **로그인 없이 쓸 수 있다** (지금 입력 화면과 같음). 비로그인 사용자는 기업 진단·맞춤 추천·수출 로드맵의 입력 버튼으로 들어온다.
- 단계 지정 `?step=1~6`은 그대로다.
- **바꾸지 않는 것:** 입력 폼과 6단계, 항목, 검증, 임시 저장·저장, 저장 키, `처음부터 다시 입력`, `입력 현황`·도움말 카드, 한 줄 설명, 완료 후 기업 진단으로 이동.
- **기존 주소 리다이렉트** (쿼리·해시 유지, 로그인 요구 없음):

  | 기존 주소 | 새 주소 |
  |---|---|
  | `/diagnose/input` | `/profile` |
  | `/diagnose` | `/profile` |
  | `/mypage/profile` | `/profile` |
  | `/mypage` | `/profile` |

### 6.2 연결

| 위치 | 버튼·링크 | 연결 |
|---|---|---|
| 프로필 팝업 | 기업 프로필 | `/profile` |
| 기업 진단 (제목 옆) | 기업정보 수정하기 | `/profile` |
| 기업 진단 (수출단계 미진단 안내) | 수출액 입력하기 | `/profile?step=3` |
| 기업 진단 (빈 상태, 확인이 필요한 항목) | 기업정보 입력하기, 빠진 항목 입력하기 | `/profile` |
| 맞춤 추천 (제목 아래) | 기업정보 입력하기 / 기업정보 수정 | `/profile` |
| 맞춤 추천 (공고가 없을 때 빈 상태) | 기업정보 확인하기 | `/profile` |
| 공고 상세 조건 목록 (`입력 없음`) | 기업정보 입력하기 | `/profile?step=n` |
| 수출 로드맵 (지금 할 수 있는 일) | 기업정보 입력·수정 | `/profile` |

- 버튼 문구는 그대로 두고 연결 대상만 바꾼다.
- `기업 맞춤 지원사업` 하위 메뉴에서 `기업정보 입력·저장`을 뺀다. 주 메뉴를 누르면 첫 하위 메뉴인 `기업 진단`이 열린다.

### 6.3 기존 기업 프로필 화면 삭제

- 헤더 프로필로 들어가던 기존 `기업 프로필` 화면(`views/mypage/ProfileView.vue`, 경로 이름 `mypage-profile`)을 지운다. 주소 `/mypage/profile`은 §6.1처럼 새 기업 프로필로 보낸다.
- **화면만 지운다.** 저장된 기업정보를 지우는 코드를 실행하거나 추가하지 않는다. 그 화면이 쓰던 공용 컴포넌트(`ProfileSummary`, `ProfileStatusBadge`, `LocalModeNotice` 등)는 지우지 않는다.
- 그 화면에만 있던 기능은 아래처럼 다른 곳에서 계속 쓸 수 있게 한다.

  | 기존 기업 프로필 화면의 기능 | 처리 |
  |---|---|
  | 입력한 기업정보 요약과 단계별 `수정` 버튼 | 기업 진단의 `입력한 기업정보` 요약에서 단계별 `수정` 버튼을 켠다(`ProfileSummary`의 `editable`, 누르면 `/profile?step=n`). 그 카드의 `프로필에서 보기` 버튼은 `기업 프로필에서 수정`(→ `/profile`)으로 바꾼다 |
  | `이 기기에서 삭제` (확인 창 → `clearAll`) | 기업 프로필의 `처음부터 다시 입력`(확인 창 → 같은 `clearAll`)이 같은 기능이다. 그대로 두고 새 삭제 버튼은 만들지 않는다 |
  | 저장 상태 (프로필 상태, 마지막 저장, 확인이 필요한 항목) | 기업 프로필의 `입력 현황` 카드에 있다 |
  | 개인정보 보호 안내 | 기업 프로필 위쪽의 `입력 정보는 이 기기에만 저장됩니다` 안내에 있다 |

## 7. 지원사업 관리 (새 주 메뉴)

- 섹션 키 `manage`, 이름 `지원사업 관리`, **로그인 필요**(지금 마이페이지와 같음).

  | 하위 메뉴 | 새 주소 | 경로 이름 | 기존 주소 |
  |---|---|---|---|
  | 관심·준비 중·신청완료 사업 | `/manage/programs` (`?tab=interested\|preparing\|applied`) | `manage-programs` | `/mypage/programs` |
  | 서류함 | `/manage/documents` | `manage-documents` | `/mypage/documents` |

- 두 화면의 내용은 그대로다(상태 탭, 패널, 비교 체크박스와 하단 비교 바, 서류함 안내). 파일 위치(`views/mypage/`, `components/mypage/`)는 옮기지 않아도 된다.
- **기존 주소 리다이렉트** (쿼리·해시 유지):

  | 기존 주소 | 새 주소 |
  |---|---|
  | `/mypage/programs` | `/manage/programs` |
  | `/mypage/documents` | `/manage/documents` |
  | `/mypage/saved` · `/mypage/preparation` · `/mypage/history` | `/manage/programs?tab=interested` · `preparing` · `applied` |
  | `/manage` | `/manage/programs` |
  | `/mypage/calendar` | `/programs/calendar` (지금과 같음) |

- 비로그인 상태에서도 주 메뉴와 하위 메뉴 패널에 보인다. 누르면 `/login?redirect=…`로 갔다가 로그인 후 그 화면으로 돌아온다(§4).
- 공고 상세의 `목록으로`: 관리 목록에서 여는 상세 링크는 `?from=manage`로 바꾸고, 이전 링크의 `?from=mypage`도 계속 받아 `관심·준비 중·신청완료 사업`으로 돌아가게 한다.

## 10. 테스트

기존 테스트는 바뀐 이름·주소에 맞게 고치고, 아래를 추가한다.

- **경로:** `/profile` → `company-profile`, `/manage/programs` → `manage-programs`, `/manage/documents` → `manage-documents`. `mypage-profile`·`diagnose-input`이라는 이름의 경로는 없다. `/roadmap`, `/diagnose/result`, `/programs/recommended`는 그대로다.
- **로그인 필요:** `/manage/programs`, `/manage/documents`, `/community/reviews/write`만 필요하다. `/`, `/profile`, `/diagnose/result`, `/programs/recommended`, `/programs`, `/roadmap`, 커뮤니티 읽기는 필요 없다.
- **섹션 값:** `/roadmap` → `roadmap`, `/programs/recommended` → `find`, `/manage/programs` → `manage`, `/profile`과 `/` → 없음.
- **리다이렉트:** `/diagnose/input?step=3` → `/profile?step=3`, `/mypage/profile` → `/profile`, `/mypage` → `/profile`, `/mypage/programs?tab=applied` → `/manage/programs?tab=applied`, `/mypage/documents` → `/manage/documents`, `/mypage/history?x=1` → `/manage/programs?x=1&tab=applied`, `/manage` → `/manage/programs`.
- **로그인 후 이동:** redirect 없이 로그인하면 `/roadmap`, `redirect=/manage/programs`면 `/manage/programs`, 거부되는 redirect면 `/roadmap`, 로그인 상태에서 `/`를 열면 `/roadmap`, 로그아웃하면 `/`.
- **데이터 보존:** 4개 저장 키에 값을 넣고 로그아웃·화면 이동·기존 주소 리다이렉트를 거친 뒤에도 값이 그대로다.
- **상단 메뉴:** 주 메뉴 5개가 §3.1 순서·이름이고, 주 메뉴 목록 안에 아이콘(svg)이 없다. 마우스를 올리거나 포커스가 들어오면 하위 항목 9개가 보이고, `Esc`나 마우스가 벗어난 뒤(150ms) 다시 숨는다. 현재 화면 항목에 `aria-current="page"`가 있다.
- **프로필 팝업:** 로그인 상태에서 버튼을 누르면 `기업 프로필`·`로그아웃` 2개만 보이고, `Esc`로 닫히며 포커스가 버튼으로 돌아온다. `로그아웃`은 `auth.logout()` 뒤 `/`로 가고 저장 키를 지우지 않는다. 비로그인에서는 `로그인` 링크가 redirect 없이 `/login`을 가리킨다.
- **기업 진단:** `기업정보 수정하기`가 `/profile`을 가리키고, 요약의 단계별 `수정`이 `/profile?step=n`을 가리킨다.
- `safeRedirect` 테스트의 예시 경로를 `/profile`, `/manage/programs?tab=applied`로 바꾼다.
